# Mini NPU Simulator

## 1. 프로젝트 소개

이 프로젝트는 AI의 기본 연산 중 하나인 MAC(Multiply-Accumulate)을 Python으로 구현한 콘솔 애플리케이션이다.

필터(Filter)는 특정 패턴을 판별하기 위한 기준을 숫자 배열로 정의한 것이다.
입력 패턴과 필터의 같은 위치에 있는 숫자를 곱하고, 그 결과를 모두 더해 점수를 계산한다. Cross(십자가) 필터와 X 필터의 점수를 비교하여 입력 패턴을 판별한다.

외부 라이브러리 없이 Python 표준 라이브러리만 사용한다.

## 2. 개발 환경

- Python 3.8 이상
- 사용 라이브러리: `json`, `re`, `time`
- 외부 라이브러리: 사용하지 않음

## 3. 파일 구성

```text
project/
├── main.py
├── data.json
└── README.md
```

`main.py`와 `data.json`은 같은 폴더에 둔다.

## 4. 실행 방법

터미널에서 프로젝트 폴더로 이동한 뒤 실행한다.

```bash
python main.py
```

- `1`: 3×3 필터 A, B와 입력 패턴을 직접 입력한다.
- `2`: `data.json`을 읽어 여러 크기의 패턴을 일괄 분석한다.
- `0`: 프로그램을 종료한다.

## 5. data.json 구조

제공된 데이터 파일에는 다음과 같은 최상위 구조가 있다.

- `meta`: 데이터 버전과 유형 정보
- `filters`: `size_5`, `size_13`, `size_25` 크기별 필터
- `patterns`: `size_{N}_{idx}` 형식의 테스트 패턴

각 크기의 필터는 `cross`, `x` 키 아래에 N×N 숫자 배열을 가진다. 각 패턴은 `input`에 N×N 배열, `expected`에 정답 라벨을 가진다.

제공된 실제 데이터의 테스트 케이스는 총 6개다.

- `size_5_1`, `size_5_2`
- `size_13_1`, `size_13_2`
- `size_25_1`, `size_25_2`

`expected`에는 `x`와 `+`가 사용된다. 프로그램은 이를 각각 `X`, `Cross`로 정규화한다. `meta`는 데이터의 부가 정보이며 분석에는 필수로 사용하지 않는다.

실행할 때는 제공된 JSON 내용을 `data.json`이라는 파일명으로 저장하고 `main.py`와 같은 폴더에 둔다.

## 6. 구현 요약

### 6-1. 2차원 배열

패턴과 필터는 중첩 리스트로 저장한다. 예를 들어 3×3 배열은 리스트 안에 3개의 행 리스트가 있는 구조다. `matrix[row][column]`으로 특정 위치의 값을 읽는다.

### 6-2. MAC 연산

`mac_operation()` 함수는 두 배열의 크기를 먼저 검증한 다음 중첩 반복문으로 같은 위치의 값을 곱해 누적한다.

```python
score = 0.0

for row in range(size):
    for column in range(size):
        score += pattern[row][column] * filter_matrix[row][column]
```

N×N 배열에는 N²개의 원소가 있으므로 MAC 연산의 곱셈과 누적은 각각 N²번 수행된다.

### 6-3. 라벨 정규화

`normalize_label()` 함수에서 입력 라벨을 표준 라벨로 변환한다.

| 입력 데이터 | 표준 라벨 |
|---|---|
| `+`, `cross`, `Cross` | `Cross` |
| `x`, `X` | `X` |

데이터를 입력한 사람이 대소문자나 기호를 다르게 사용해도 프로그램 내부에서는 동일한 라벨로 비교할 수 있다. 알 수 없는 라벨은 임의로 해석하지 않고 오류로 처리한다.

### 6-4. 부동소수점과 epsilon

컴퓨터의 실수 연산은 10진수를 항상 정확하게 표현하지 못할 수 있다. 따라서 이론적으로 같은 값이어도 아주 작은 차이가 발생할 수 있다.

이 프로그램은 다음 기준을 사용한다.

```python
EPSILON = 1e-9

if abs(score_a - score_b) < EPSILON:
    return "UNDECIDED"
```

두 점수의 차이가 0.000000001보다 작으면 동점으로 간주한다. 동점일 때 어느 한쪽을 임의로 선택하지 않고 `UNDECIDED`를 반환한다.

### 6-5. 입력 및 JSON 검증

`validate_matrix()`는 배열이 비어 있는지, 각 행의 열 개수가 N인지, 모든 원소가 숫자인지 확인한다.

사용자 입력 모드에서는 행마다 숫자 개수가 잘못되거나 숫자로 변환할 수 없는 값이 있으면 오류를 출력하고 다시 입력받는다.

JSON 모드에서는 케이스별로 오류를 처리한다. 예를 들어 필터가 없거나 배열 크기가 맞지 않는 케이스는 FAIL로 기록하고, 다음 케이스 분석을 계속한다.

### 6-6. 성능 측정

`time.perf_counter()`로 MAC 함수 호출 구간을 측정한다. 파일 읽기와 콘솔 출력 시간은 측정 구간에서 제외한다.

각 크기마다 MAC 연산을 10회 반복하고 총 소요 시간을 10으로 나누어 평균 시간을 구한다. 측정 전에 1회 워밍업을 수행한다.

## 7. 결과 리포트

### 7-1. 실패 원인 분석

실패 원인은 크게 데이터/스키마 문제, 로직 문제, 수치 비교 문제로 나누어 분석할 수 있다.

1. 데이터/스키마 문제는 JSON 키 이름이나 데이터 구조가 프로그램이 기대하는 형식과 다를 때 발생한다.
2. 예를 들어 `size_5_1` 대신 다른 키 형식을 사용하면 크기 N을 추출할 수 없다.
3. 필터의 행과 열 개수가 N×N이 아니거나 `input` 항목이 빠져 있어도 해당 케이스는 FAIL 처리된다.
4. 라벨 정규화는 `+`와 `cross`를 모두 `Cross`로 바꾸어 라벨 표기 차이로 인한 비교 오류를 줄인다.
5. 로직 문제는 MAC 연산에서 행 또는 열의 인덱스를 잘못 사용하거나 곱셈 결과를 누적하지 않을 때 발생할 수 있다.
6. 이 프로그램은 두 배열의 크기를 먼저 확인하고 동일한 위치끼리 곱하므로 크기 불일치로 인한 잘못된 연산을 방지한다.
7. 수치 비교 문제는 부동소수점 표현 오차 때문에 발생할 수 있다.
8. 단순히 `score_a == score_b`로 비교하면 실제로 거의 같은 점수를 동점으로 처리하지 못할 수 있다.
9. 이를 방지하기 위해 두 점수의 차이에 epsilon 기준인 `1e-9`를 적용했다.
10. 점수 차이가 epsilon 미만이면 `UNDECIDED`로 판정하며, expected가 Cross 또는 X라면 해당 케이스는 FAIL이 된다.
11. 따라서 동점으로 인한 FAIL은 프로그램 오류가 아니라 명시한 판정 정책에 따른 결과일 수 있다.
12. 전체 FAIL이 0개라면 모든 케이스의 입력 구조와 크기가 유효했고, 예측 결과가 expected와 일치했다는 의미다.
13. 라벨 정규화와 epsilon 정책은 표기 차이와 부동소수점 오차를 줄이는 역할을 하지만, 잘못된 정답 라벨이나 부적절한 필터 자체를 자동으로 수정하지는 않는다.

### 7-2. 시간 복잡도 분석

MAC 연산은 N×N 배열의 모든 원소를 한 번씩 방문한다.

| 배열 크기 | 연산 횟수 N² |
|---|---:|
| 3×3 | 9 |
| 5×5 | 25 |
| 13×13 | 169 |
| 25×25 | 625 |

바깥 반복문은 N번, 안쪽 반복문도 N번 실행된다. 따라서 전체 반복 횟수는 N×N이며 시간 복잡도는 O(N²)이다.

3×3 배열은 9번 연산하지만 25×25 배열은 625번 연산한다. 배열의 한 변 길이가 커질수록 전체 원소 수가 제곱에 비례해 증가한다.

다만 실제 측정 시간은 반복문 실행 비용뿐 아니라 Python 인터프리터, 함수 호출, 운영체제 스케줄링 등의 영향을 받는다. 따라서 측정값이 연산 횟수에 정확히 비례하지 않을 수 있다.

성능 표의 시간은 지정한 환경에서 10회 반복한 평균값이며, 실행할 때마다 조금씩 달라질 수 있다. 이 측정은 CPU에서 Python 반복문으로 MAC을 수행하는 시간이지 실제 NPU 하드웨어의 성능을 측정한 것은 아니다.

## 8. 제공된 data.json 실행 결과

제공된 실제 데이터 6개 케이스를 실행했을 때 결과는 다음과 같다.

| 케이스 | Cross 점수 | X 점수 | 판정 | 결과 |
|---|---:|---:|---|---|
| size_5_1 | 0.9 | 0.9 | UNDECIDED | FAIL |
| size_5_2 | 8.9 | 0.1 | Cross | PASS |
| size_13_1 | 0.3 | 14.7 | X | PASS |
| size_13_2 | 7.5 | 7.5 | UNDECIDED | FAIL |
| size_25_1 | 4.9 | 4.9 | UNDECIDED | FAIL |
| size_25_2 | 52.9 | 0.1 | Cross | PASS |

- 전체 테스트: 6개
- 통과: 3개
- 실패: 3개

실패한 세 케이스는 모두 Cross 점수와 X 점수가 같다. epsilon 기준으로 동점 처리되어 `UNDECIDED`가 반환되며, expected는 Cross 또는 X로 지정되어 있으므로 FAIL이다. 이는 MAC 계산 오류가 아니라 과제에서 정한 동점 판정 정책에 따른 결과다. 따라서 이 케이스들을 임의로 PASS 처리하지 않는다.

## 9. 테스트 및 재현성

### 사용자 입력 모드

3×3 십자가 필터와 X 필터를 각각 입력한 뒤 십자가 패턴을 입력하면 다음 점수가 나와야 한다.

- 십자가 필터 점수: 5
- X 필터 점수: 1
- 판정: A (필터 A에 십자가를 입력한 경우)

필터 A와 B의 입력 순서를 바꾸면 판정도 그에 맞게 바뀌어야 한다.

### JSON 모드

`data.json`에 포함된 각 패턴을 분석하고 Cross 점수, X 점수, 예측 라벨, expected, PASS/FAIL을 출력한다. 마지막에는 전체 테스트 수, 통과 수, 실패 수와 실패 사유를 출력한다.

### 오류 테스트

- 행 또는 열의 숫자 개수가 맞지 않는 사용자 입력
- 숫자로 변환할 수 없는 사용자 입력
- JSON 파일 누락 또는 JSON 문법 오류
- 패턴 키 형식 오류
- 필터와 패턴의 크기 불일치
- 필수 필드 누락
- 지원하지 않는 라벨

오류가 발생해도 JSON 모드에서는 해당 케이스를 FAIL로 기록하고 가능한 다음 케이스를 계속 분석한다.
